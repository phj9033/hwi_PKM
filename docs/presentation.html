why · 문제정의

왜 또 PKM인가?

대부분의 노트앱은 저장은 잘 하지만 누적은 안 된다. 매 검색마다 같은 출처를 다시 읽고, 같은 답을 다시 합성한다. Compounding(누적 합성)이 핵심이다.

기존 노트앱

매번 똑같은 일을 다시 한다

검색 → 읽기 → 합성을 매번 반복. 결과물은 사라지고, 출처만 늘어난다.

hwi_PKM

합성한 답이 wiki로 누적된다

capture → review → promote → wiki. 한 번 합성한 답은 다음에 즉시 검색·재사용.

3가지 결과

RESULT · 01

API 키 0개로 운영

임베더·재랭커는 로컬. 외부 LLM은 옵트인. 비밀번호 노출 위험 없음.

RESULT · 02

Markdown만 백업하면 끝

인덱스 DB·대시보드는 모두 markdown에서 재생성. 락인(lock-in) 없음.

RESULT · 03

AI가 직접 못 망친다

위키 직접 쓰기 차단. 승격 경로는 grounding gate 통과 필수.

architecture · 핵심 그림

3-Layer 아키텍처

역할이 다른 세 레이어가 명확히 분리되어 있다. 위에서 아래로: 의사결정자 → 실행자 → 진실.

layer 1

AI 에이전트 (Operator)

의사결정. "이 캡처는 wiki로 갈 만한가?", "이 문맥을 어떻게 합성할까?"
Claude Code 세션 SCHEMA.md .claude/commands/*.md (9종) deny-write 권한
↓
shell exec
layer 2

pkm CLI (Deterministic Core)

실행. LLM SDK 없음, API 키 없음 — 같은 입력 → 같은 출력 보장.
capture · chunks · extract reindex · search · related promote · demote · wiki edit write · lint · dashboard project · session · install
↓
read · write
layer 3

Data + Caches (Source of Truth)

진실. 모든 것은 마크다운에서 결정론적으로 재생성된다.
data/ (markdown = truth) .pkm/index.db (SQLite + vec0) ~/.cache/pkm/models/ (~8 GB) dashboard/ (정적 HTML)

핵심 경계

Markdown = 진실. .pkm/index.db·dashboard/는 항상 재생성 가능. gitignore.
CLI = 결정론. LLM SDK import 없음. 임베더는 로컬 실행, 외부 호출 없음.
AI 셸아웃 = 옵트인. --expand 같은 옵션에서만 사용자 환경의 claude/codex/gemini를 자동탐지.
자동 git 커밋. 모든 mutate 명령은 데이터 repo에 자동 커밋 — git log가 곧 활동 감사로그.
principles · 설계 철학

핵심 원칙 4가지

모든 설계 결정은 이 4개 원칙에서 파생된다. 충돌 시 우선순위: 1 → 2 → 3 → 4.

PRINCIPLE · 01

Markdown = Source of Truth

인덱스·대시보드·캐시는 모두 markdown에서 재생성 가능. markdown만 백업하면 끝.

PRINCIPLE · 02

CLI는 결정론(Deterministic)

같은 입력 → 같은 출력. LLM SDK import 없음, API 키 없음, 외부 네트워크 호출 없음.

PRINCIPLE · 03

AI는 옵트인 셸아웃

--expand 같은 옵션에서만 사용자 환경의 AI CLI를 셸로 호출. 활용은 하되 의존하지 않음.

PRINCIPLE · 04

Lifecycle Gates

아무 글이나 wiki로 못 간다. reviewed, final, 인용 정합성 등 게이트 통과 필수.

lifecycle · 노트의 일생

데이터 라이프사이클

모든 노트는 raw → review → promote → wiki 경로를 거친다. 중간 어디서든 멈출 수 있고, 한 번 wiki로 가면 다음 검색에 즉시 잡힌다.

· 단순 경로 (단일 URL → wiki) ·

· 합성 경로 (여러 출처 → writing → wiki) ·

왜 게이트가 중요한가? wiki가 곧 검색 인덱스의 우선 채널이다. 검증 안 된 글이 들어가면 다음 검색·합성이 그 위에서 진행되어 오류가 누적된다.

operations · 일상 운용

AI 운영 모델

Claude Code 세션 안에서 슬래시 커맨드 한 줄로 끝낸다. AI는 의사결정만, 데이터 mutate는 모두 pkm CLI를 거친다.

주요 슬래시 커맨드

/collect <url>

URL → 요약·태그 → capture create --status draft

/research <topic>

WebSearch + WebFetch → 3~6 capture + 옵션 chunks

/review-captures

draft 순회 → reviewed 전환 또는 삭제

/promote

reviewed 검토 → bucket 결정 → pkm promote

/ask <질문>

검색 → top-K Read → 인용 grounded 답변 (추측 금지)

/write <topic>

writing 생성 → 인용하며 작성 → final → promote

/lint [--fix]

정합성 검사 + 자동 수정

/blog --random

랜덤 wiki 카드 → 블로그 시드 초안

글로벌 통합 (V3 / M14)

코드 repo 어디서든 /pkm-recall, /pkm-extract-session, /pkm-backfill로 PKM에 접근. 코드 세션이 PKM 컨텍스트와 즉시 연결된다.

summary · 한 슬라이드로

정리

기억해야 할 다섯 가지.

  1. 마크다운이 진실이다. 모든 인덱스·대시보드는 markdown에서 결정론적으로 재생성된다.
  2. CLI는 결정론, AI는 옵트인. 핵심 기능은 API 키 0개로 동작한다.
  3. 라이프사이클 게이트로 누적을 보호한다. reviewed → grounding gate → wiki. 검증 안 된 글은 못 들어간다.
  4. 3-Layer로 책임이 분리되어 있다. AI(결정) ↔ CLI(실행) ↔ Data(진실) — 한쪽이 깨져도 다른 쪽이 흔들리지 않는다.
  5. Compounding이 핵심 가치다. 한 번 합성한 답은 다음 검색에 즉시 잡힌다 — 시간이 지날수록 더 똑똑해진다.
